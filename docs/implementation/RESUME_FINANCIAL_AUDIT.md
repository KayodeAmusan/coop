## Alternate entry-point trace and immediate priorities

1. `loan/api/loan.php` starts a session but performs no authorization; POST `insert_loan` writes `tbl_loans` and `post_account` writes approvals through `loan/classes/LoanManager.php`. Neither operation checks evidence, product publication, financial posting or command receipts. Its GET reads also expose member/batch financial information without an explicit authorization check. Deployment reachability has not been established, so do not call these successfully exploited endpoints; treat web-root source as an uncontained route.
2. `loan/postAccount_.php?batchid=...` deletes existing approvals then inserts rows from `excel` without auth, transaction or consent.
3. `api/loan-processor.php` accepts a legacy session but not finance/loan capability; `updateLoan` disables limit validation, uses floats and a hardcoded 12-month schedule, and inserts/updates approvals; `deleteLoan` removes history. `classes/process.php::processPendingLoans` consumes these approvals into actual loan/master posting. Consent in modern admin approval cannot protect this path.
4. `classes/controller.php?act=update_deductions` writes three tables from float inputs without an authorization guard in the shown dispatcher, transaction or command receipt. `api/upload_json_data.php` does require exact Admin but retains float parsing/evolving upserts. Backup/copy controller aliases require separate reachability containment; existing idempotency audit is a lead, not verification.
5. `transaction-summary.php` accepts another member's CoopID after JWT validation. It also logs request headers/Authorization on malformed auth. Fix the identity boundary and avoid logging secrets before broader new functionality.

Dependency backlog: (1) contain legacy unauthorized reads/mutations and bind member identity; (2) centralize exact/idempotent financial writes and canonical disbursement; (3) publish configured loan products + commitment capacity; (4) deposit verification and expected/actual deduction imports; (5) product-backed reservations/refunds/exit; (6) share ownership/settlement; (7) frozen exact bonus distribution; (8) unify statements/reports and rehearse migration/reconciliation. Each item needs real APIs, screens, permissions, audit/outbox and synthetic regression checks before Implemented.
